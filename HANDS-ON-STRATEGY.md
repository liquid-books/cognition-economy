# HANDS-ON STRATEGY — Keeping the Doing in the Evergreen Edition

*Prepared for Dr. Lee, August 2026. Survey of drafts/ (ch00–ch14 present) plus originals in chapters/ (ch15–ch16 not yet drafted). No drafts or originals were modified.*

**Bottom line up front:** The revision did NOT gut the book. Roughly 85% of the doing-value survives in print, because Track A was always where the pedagogy lived and Tracks B/C were mostly click-path duplication of the same lesson. But the revision was applied inconsistently — two different patterns coexist in the drafts — and three chapters (13, 16, and to a lesser degree 6) genuinely lost hands-on substance that should come back in evergreen form. The fix is not "restore the tracks." The fix is to standardize on the best pattern the draft agents already invented (ch09/ch10's dial-per-step tracks), upgrade the "Is this still true?" sidebars from disclaimers into labs, and add inline doing so the exercises aren't all stacked at chapter end.

## Part 2 — Where Hands-On Thinned (Honest Assessment)

**First, the good news, stated plainly:** the fear that the revision "guts the hands-on character" is mostly unfounded. Track A was never the consolation-prize track — it is where the book's real exercises live: the Context Brief, the meta-prompting interview, the three-skill build, the six-floor climb, the plan-pushback discipline, the memory file, the reflection loop, the security audit. All of that is in print, richer than before in places (ch04's demonstrate-it path, ch03's permission-screen contract, ch08's promoted live-data test). What moved online was overwhelmingly *buttons*: CMD+E, `/agents` wizards, version flags, doc URLs. Students lose nothing pedagogically by getting buttons from a date-stamped page instead of a stale book.

**But four real losses, ranked:**

1. **Ch 13 — the automation is gone from print.** The manual-version exercise is well designed as a *first step* ("the alarm IS your schedule" is a genuinely good teaching move), but the chapter now ends where the original's Track A ended. The student who does only what's printed never configures a trigger, never selects a channel, never receives an artifact they didn't ask for in the moment. For a masterclass whose thesis is proactive AI, the printed floor is too low.

2. **Ch 16 — capstone build at risk.** Not yet drafted, so this is a warning, not a loss: the original Track C is the only exercise where a student *builds* the tissue architecture the whole book argues for. If the drafting agent applies the COLLAPSE pattern here, the capstone submission becomes a document about a design instead of a running configuration plus its output. Do not let that happen.

3. **Ch 06 — the comparison experiments went online.** The printed sequence (plan → skeptical read → pushback → execute) is strong, but the two most persuasive experiences — *watching* a plan execute step by step, and running the same task with and without a plan and comparing — are companion-only. The second one doesn't even need a terminal; it runs in any chat window. Its exile is unjustified.

4. **Ch 02 / ch 05 — the second and third surfaces became rumors.** The COLLAPSE chapters describe the terminal agent and orchestration workspace in one recurring paragraph and wave at the companion page. A student who never clicks through will finish the course having *read about* two of the three surface types the book claims to teach on. Ch09/ch10 prove this was avoidable: their in-print Tracks B/C are fully de-branded, teach "which dial each step sets," and defer only the literal click-path.

**Structural inconsistency (the real editorial problem):** the drafts contain two philosophies. Ch09/ch10 (DIAL) treat Tracks B/C as *print pedagogy with online buttons*. Ch02/05/06/11/12/13/14 (COLLAPSE) treat Tracks B/C as *online content with a print apology*. Both patterns cite the same audit Move 1. The book needs one philosophy, and DIAL is the right one wherever the surface changes what is learned. Additional inconsistencies: ch11's collapse contradicts the audit's own "leave alone all three exercise tracks"; ch12 and ch13 lack the verify sidebar that Move 5 mandates for tool-heavy chapters (ch13 is the most tool-heavy chapter in the book); ch01.md was never reassembled from its revised sections (md5 identical to the original — the printed exercise still contains arena.ai click-paths, $20/$17 pricing, ⌘+Shift+Space).

## Part 3 — Recommended Strategy

### 3.1 Adopt the DIAL pattern book-wide; retire the COLLAPSE pattern where the surface matters

**The test:** *Does doing this exercise on surface B or C teach something surface A cannot?* If yes, the track stays in print, written the ch09 way — every step named for the evergreen thing it sets ("Set the scope dial: personal… Exact click-path: companion site"), plain-English commands instead of syntax ("Tell the agent: create a two-teammate team, name them Alex and Sam…"), submission block intact. If no — if B/C is the same conversation on a different surface — collapse is correct and should stand.

Applying the test:

- **Keep collapsed (COLLAPSE was right):** ch02 (setup is setup), ch03, ch04, ch07, ch08, ch11 (the chat exercise *is* the lesson — but confirm against the original tracks before finalizing), ch12, ch14.
- **Restore in-print tracks, DIAL-style:** **ch05** (the file-based climb: floors 2–5 as files in a working folder is a different mental model than settings screens — one printed track, "The Six Floors as Files," is enough), **ch06** (see 3.3), **ch13** (see 3.3 — this is the priority), and **ch15/ch16 when drafted** (instruction to drafting agents: apply DIAL, not COLLAPSE; ch16 Track C's peer-agent build must survive in print in plain-English form — "Create a project with three peer agents and no lead; here is the brief for each; run this real task through it" is evergreen; only the workspace's current name and toggle belong online).

### 3.2 Upgrade "Is this still true?" sidebars from disclaimers to Verification Labs

The sidebars are the revision's sleeper asset. Some are already active exercises (ch05's "ask your AI what it knows about you — whatever it says is the memory layer you don't control"; ch04's "try to open one of your own skills as a file — if you can't, you don't own it"). Others are passive ("check the companion site"). Standardize on the active form:

- **Rename the pattern** in the book's front matter: these are not disclaimers, they are *the sixth discipline in miniature* — the professional habit of verifying vendor reality against printed claims. Frame them once, in "A Note on Names, Numbers, and Buttons": *"Every tool-heavy chapter ends with a two-minute lab. Run it. The answers you log are how you keep this book current yourself."*
- **Format:** 2–3 numbered checks, each a *do* with a *logged artifact* ("Run this. Write down the answer."), closing with the companion pointer. Never lead with "check the website" — lead with something the student runs against their own tool.
- **Make them submittable.** One line in each chapter's submission block: "Append your verification log — the dated answers to this chapter's Is This Still True checks." Now the sidebar is graded work, and every semester the class collectively re-audits the book. (Instructor bonus: harvest the logs each term to update the companion pages. The students become the book's maintenance crew — tell them so; they'll love it.)
- **Fill the gaps:** add labs to ch12 (light: "ask your assistant whether it remembers your last feedback — did the lesson persist without your memory note?"), ch13 (mandatory: "ask your assistant what channels it can deliver to today, and whether it can run a task on a schedule — log the answers"), ch01 (the audit's §1.7 "How to verify" context-window box), ch15/ch16 when drafted.

### 3.3 Bring three things back into print, in evergreen form

1. **Ch 13 — the automation build, evergreen version.** Add "Part 3: Automate It (15 minutes)" after the manual version. Evergreen because it's plain English, not configuration: *"Open your agent surface and say: 'Every weekday at 8:00 AM, run the briefing specification I'm about to paste, and deliver it to [the channel where you actually read things]. Confirm what you've scheduled and show me how to inspect or cancel it.'* If your tool can't schedule tasks yet, that's a logged verification answer — run the manual version and check the companion page for what shipped since press time." Trigger, work, channel — the chapter's own taxonomy — each named in one sentence the student *speaks to the tool*. The click-path stays online; the *act of delegation* comes back to print. The chapter's promise is restored: the student wakes up to a briefing they did not ask for that morning.
2. **Ch 06 — the run-twice experiment.** Currently companion-only ("orchestration-workspace version"), but it is tool-agnostic: *"Run your real task once cold, in a fresh session, with no plan step. Compare against the planned output. Add both to your submission with one sentence on the difference."* Ten minutes, any chat window, and it converts the chapter's thesis from claim to experienced fact. Print it as Step 6.
3. **Ch 15 — the longitudinal thread, manual form.** When drafting: keep the scorecard conversation (Track A) and add the time axis without automation: *"Put a 30-day recurring event on your calendar: 're-score my role.' Paste your previous score into the session and ask what moved."* The B/C automated version goes online; the discipline of tracking is print.

Also: **reassemble ch01.md** from its revised sections and rebuild its exercise per the audit (goals in print, arena.ai as press-time example, click-paths and prices to drlee.io/ch1) — right now the flagship chapter's exercise is the most perishable one in the drafts folder purely because the assembly step didn't happen.

### 3.4 Add "Do This Now" boxes — inline doing, not just end-of-chapter doing

The revision concentrated all doing at chapter end. A masterclass companion should interrupt reading with action. Add 1–3 per chapter, one admonition type, strict rules:

- **60–120 seconds each.** One paste-prompt, one check, or one note-to-file. Never a click-path.
- **Evergreen only.** If the action needs a button name, it's not a Do This Now — it's a companion-page task, and the box instead says *"Companion task: [what you'll do and why it's worth doing] → drlee.io/chNN."* (That reframing matters: pointers should promise an experience, not apologize for an absence.)
- Natural candidates already latent in the text: ch01 §1.4 "tokenize one of your own emails right now"; ch03 permission-screen reading during the connector flow; ch05 after Discipline Three "paste the meta-prompt interview and answer its first question"; ch06 after the core planning prompt "run it on the email you were going to write after this chapter"; ch09 after the Test Question "apply it to the last task you delegated to a human."

### 3.5 Companion-site structure — make Tracks B/C first-class, not demoted

The print pointers only work if the destination feels like the book's second half, not its overflow bin.

- **URLs and QR:** one short URL per chapter (`drlee.io/chNN`, already consistent in drafts) + a QR code in each chapter's exercise header. One scan, zero typing. Top of every page: date stamp + "what changed since the printed edition" changelog (three lines, dated — this *demonstrates* the book's perishability thesis every time a student visits).
- **Versioned track sheets:** each B/C track is a numbered, versioned document — "Ch 10 · Track B · v. Fall 2026" — in the book's voice, with the same submission block as print, mirroring the printed step numbers so instructor and student can say "step 4 on your sheet." Archive old versions (a Spring 2027 student can see what Fall 2026 looked like — itself a lesson in tool churn).
- **Parity rule:** every printed exercise states, where true, "Tracks B and C are graded equally; pick the surface that matches how you want to work." Demotion is a framing problem as much as a location problem — kill the framing.
- **Instructor cadence:** a semester-start checklist (30–60 min): re-run every verification lab, bump track-sheet versions, update the model roster page, post the changelog. Feed in last term's student verification logs (3.2). This is the mechanism that makes "evergreen book + living companion" an operating system rather than a hope.
- **One page per chapter, not a portal.** Students should never navigate. Print URL → chapter page → everything for that chapter: track sheets, current click-paths, screenshots, the dated roster/comparison tables the print edition exiled, and the current links (registry, agentskills.io, pricing pages).

## Part 4 — Standard Per-Chapter Exercise Architecture (Evergreen Edition)

Every tool-facing chapter (2–14, plus 15–16 capstones) ships this skeleton, in this order:

```
1. DO THIS NOW boxes (1–3, inline in the body)
   60–120s. Paste-prompt / check / note-to-file. Evergreen only.
   Perishable equivalents appear as "Companion task: … → drlee.io/chNN".

2. CASE STUDY + Discussion Prompt        (unchanged — already evergreen)

3. APPLIED EXERCISE
   a. Header strip: time estimate · what you'll have when done ·
      QR + drlee.io/chNN · "Three Surfaces" paragraph (the standard one)
   b. CORE LAB (the former Track A, de-branded):
      real work only ("pick something with actual stakes"),
      paste-prompts verbatim in print, artifact produced,
      Submission block (unchanged format: artifacts + N sentences)
   c. SURFACE VARIANTS — apply the test:
      • If B/C teaches something A cannot → in-print DIAL track:
        steps named for the evergreen dial each one sets,
        plain-English commands to the tool, click-paths → companion,
        own submission block. (Model: ch09 Track B, ch10 Track B.)
      • If B/C is the same lesson on different buttons → one-line
        promise-framed pointer ("On the terminal agent this exercise
        saves its outputs as files in your project — walkthrough at
        drlee.io/chNN").
   d. OPTIONAL VARIANT (where it exists): the stretch exercise
      (ch13's computer-use task is the template)

4. VERIFICATION LAB  («Is this still true?» admonition)
   2–3 numbered checks. Each = run something, log the answer, date it.
   Last line only: companion pointer. Log is appended to the submission.

5. REFLECTION (2–3 sentences, single-surface-safe, plus the optional
   "if you ran more than one surface" comparison)
```

**Print/online boundary, stated as a rule the whole book can obey:** *Prompts, briefs, checklists, decision rubrics, plain-English commands, and submission formats are print. Button names, menu paths, version numbers, prices, URLs, and screenshots are companion. If a sentence would survive the vendor renaming everything, it can be printed.*
