# Chapter 3: Tools and the MCP Revolution

:::{figure} ../images/ch03-infographic.png
:label: fig-ch03-infographic
:alt: MCP gives AI hands — connecting Claude Desktop to Gmail, Drive, Calendar, databases, and the web
:width: 80%
:align: center

*Giving Your AI Hands* — Without MCP, your AI can only talk. With MCP, it can reach into your actual world.
:::

Up to this point, your AI is a brilliant conversationalist locked in a room with no windows and no door. It can reason about anything you describe to it. It can write, analyze, and advise. But it cannot see your emails, cannot read your files, cannot check your calendar, and cannot look something up on the web. Everything it knows about your world comes from what you paste into a chat window.

MCP changes that.

MCP stands for Model Context Protocol. It is an open standard — published by Anthropic — that lets AI assistants connect directly to external tools and data sources. When you install an MCP server for Gmail, your Claude Desktop can read your actual inbox. When you install one for Google Drive, it can search and summarize your actual documents. When you install one for Supabase, it can query your actual database.

This is not a metaphor. It is a literal connection. Your AI goes from being a very smart person you have to brief on everything, to being a very smart person who can look things up themselves.

This chapter focuses on three MCP connections worth installing immediately — Google Workspace, Firecrawl, and Supabase — and briefly surveys the broader landscape of what else is available.

## What MCP Actually Is

:::{figure} ../images/ch03-what-mcp-is.png
:label: fig-ch03-what-mcp-is
:alt: Before and after MCP — AI that can only talk vs AI that can act
:width: 80%
:align: center

*The MCP Difference* — The same model. The same intelligence. One version is locked in a room. The other has a door.
:::

Before MCP existed, connecting an AI to external tools required custom code, API wrappers, and significant engineering effort. Every integration was a one-off project. MCP standardizes the handshake — it defines a common protocol so that any tool built to the standard can plug into any AI that supports it.

Think of it like USB. Before USB, every peripheral had its own connector. After USB, anything that followed the standard worked with anything else that followed the standard. MCP is USB for AI tools.

From a practical standpoint, an MCP server is a small piece of software that runs on your computer alongside Claude Desktop. Claude Desktop talks to it using the MCP protocol. The server translates Claude's requests into calls to the actual tool — your Gmail account, your database, a website — and returns the results back to Claude. The whole exchange happens in seconds, and from your perspective it just looks like Claude knows things it could not have known before.

:::{figure} ../images/ch03-claude-config-file.png
:label: fig-ch03-config-file
:alt: Claude Desktop config file showing MCP server entries
:width: 80%
:align: center

*The Config File* — A JSON file that tells Claude Desktop which MCP servers to load. You add entries here once; they load automatically every time Claude opens.
:::

The technical piece you interact with is a configuration file. Claude Desktop reads a file called `claude_desktop_config.json` at startup. When you add a server entry to that file — specifying what the server is called, how to run it, and any credentials it needs — Claude Desktop loads that server automatically every time it opens. From that point on, Claude can use those tools in any conversation.

You do not need to be a developer to do this. The rest of this chapter walks you through the exact steps.

## Google Workspace: Your Day-to-Day Life, Inside Claude

This is the highest-value MCP connection most professionals can make. Your Gmail, Google Drive, and Google Calendar contain more context about your work than any document you could manually paste. Connecting them to Claude Desktop means your AI can finally see your world instead of just hearing about it.

If you do not have a Google account, create one at gmail.com before continuing. It is free. The connection requires a Gmail account because Google's authentication is tied to the Google account ecosystem.

:::{figure} ../images/ch03-google-products-value.png
:label: fig-ch03-google-value
:alt: Three Google MCP connections — Gmail, Drive, and Calendar — each with independent value
:width: 80%
:align: center

*Three Independent Connections* — Gmail, Drive, and Calendar each connect separately. Each one adds a different kind of awareness to Claude.
:::

**What you get:**

**Gmail** — Claude can search your inbox, read specific emails, find threads by sender or subject, and draft responses in your voice. Ask it to find every email from a specific client in the last 30 days, summarize the conversation, and draft a follow-up — and it does exactly that without you copying and pasting a single message.

**Google Drive** — Claude can search your Drive, open and read documents, and reason across multiple files. Drop 10 reports in a Drive folder and ask Claude to find the common themes or flag the outliers. It reads all of them.

**Google Calendar** — Claude can see your upcoming schedule, check for conflicts, identify your available windows, and factor your calendar into its recommendations. Ask it to help you prepare for tomorrow's meetings and it knows what those meetings are.

**Setting up the Google MCP connection in Claude Desktop:**

:::{figure} ../images/ch03-google-mcp-setup.png
:label: fig-ch03-google-setup
:alt: Step-by-step guide to connecting Google tools to Claude Desktop via MCP
:width: 80%
:align: center

*Google MCP Setup* — Four steps from zero to Claude reading your actual inbox.
:::

**Step 1: Install Node.js** if you do not have it. Go to nodejs.org and download the LTS version for your operating system. This is the runtime the MCP servers use. Install it and confirm it works by opening a terminal and typing `node --version`.

**Step 2: Open your Claude Desktop config file.**
- On Mac: `~/Library/Application Support/Claude/claude_desktop_config.json`
- On Windows: `%APPDATA%\Claude\claude_desktop_config.json`

If the file does not exist, create it. If it does exist, you will add to it.

**Step 3: Add the Google MCP server entries.** The community-maintained Google Workspace MCP servers cover Gmail, Drive, and Calendar. Add the following to your config file:

```json
{
  "mcpServers": {
    "google-gmail": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-gmail"],
      "env": {
        "GMAIL_CREDENTIALS_PATH": "/path/to/your/credentials.json"
      }
    },
    "google-drive": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-gdrive"],
      "env": {
        "GDRIVE_CREDENTIALS_PATH": "/path/to/your/credentials.json"
      }
    },
    "google-calendar": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-google-calendar"],
      "env": {
        "GOOGLE_CREDENTIALS_PATH": "/path/to/your/credentials.json"
      }
    }
  }
}
```

**Step 4: Create your Google credentials.** Go to console.cloud.google.com. Create a new project. Enable the Gmail API, Drive API, and Calendar API for that project. Create OAuth 2.0 credentials and download the JSON file. Save it somewhere on your computer and update the `credentials.json` paths in your config file to point to it. On first run, a browser window will open asking you to authenticate with your Google account — do so, and the credentials are saved for future sessions.

**Step 5: Restart Claude Desktop.** The servers load at startup. After restarting, you should see the MCP tools available in Claude's interface — typically indicated by a hammer icon or tools menu. Test immediately: ask Claude to tell you what emails you received today.

This connection is not a one-time trick. Once it is live, every conversation with Claude has access to your Google data when you ask for it. It becomes part of how you work.

## Firecrawl: The Web, Readable by Your AI

The public internet is one of the largest information sources in the world — and by default your AI cannot read any of it. Firecrawl fixes that.

:::{figure} ../images/ch03-firecrawl-explained.png
:label: fig-ch03-firecrawl
:alt: Firecrawl converts web pages into clean text an AI can read
:width: 80%
:align: center

*What Firecrawl Does* — A website is a mess of HTML, JavaScript, and navigation. Firecrawl extracts the actual content and hands it to your AI as clean, readable text.
:::

Firecrawl is a web scraping API that converts any website into clean, structured text that an AI can read and reason about. Give it a URL. It returns the content in a format Claude can actually use — no HTML, no noise, just the text and structure of the page.

The free account gives you 500 lifetime credits. One credit is roughly one page scrape. That sounds limited, but consider what 500 deliberate scrapes actually gets you: 500 competitor pages analyzed, 500 pricing pages extracted, 500 news articles summarized, 500 job postings collected and compared. Used intentionally, 500 credits is a meaningful research capability that costs you nothing.

:::{figure} ../images/ch03-firecrawl-use-cases.png
:label: fig-ch03-firecrawl-uses
:alt: Five high-value Firecrawl use cases for business professionals
:width: 80%
:align: center

*Firecrawl Use Cases* — 500 free credits. Use them on things that would take you hours to read manually.
:::

**Setting up Firecrawl:**

Go to firecrawl.dev and create a free account. Copy your API key from the dashboard.

Add Firecrawl to your Claude Desktop config:

```json
"firecrawl": {
  "command": "npx",
  "args": ["-y", "firecrawl-mcp"],
  "env": {
    "FIRECRAWL_API_KEY": "your-api-key-here"
  }
}
```

Restart Claude Desktop. Test it by asking Claude to read a specific URL and summarize it.

**What to use Firecrawl for:**

Competitive intelligence is the highest-value use case for most professionals. Ask Claude to read a competitor's pricing page, their about page, their most recent blog posts, and their careers page — then synthesize what it learns into a competitive brief. That research, done manually, takes hours. With Firecrawl and Claude, it takes minutes and the output is better structured than anything you would write by hand.

The discipline is intentionality. Do not burn credits on pages you could just read yourself. Use them on content that requires synthesis — multiple pages, dense reports, sites with paywalled summaries you want analyzed from what is publicly visible.

## Supabase: A Free Database Your AI Can Use

Most business professionals have never needed a database. That changes the moment you start building AI-powered workflows that need to store, retrieve, and update information at scale.

Supabase is an open-source backend platform that gives you a fully functional PostgreSQL database, serverless edge functions, and a built-in authentication system — all on a generous free tier. No credit card required to start. No server to manage. You create a project, and Supabase provisions everything automatically.

:::{figure} ../images/ch03-supabase-explained.png
:label: fig-ch03-supabase
:alt: Three Supabase capabilities — database, edge functions, authentication
:width: 80%
:align: center

*What Supabase Gives You* — Three independent capabilities. You can use one, two, or all three. The free tier covers serious workloads.
:::

**Why this matters for AI workflows:**

When your AI starts doing real work — collecting data, tracking contacts, logging decisions, managing customer records — it needs somewhere to put information that persists between conversations. Claude's context window is not persistent storage. It clears between sessions. Supabase is the persistent layer.

**The database** is a full PostgreSQL instance. Your AI can read from it, write to it, and query it in natural language — Claude can translate "find all clients who haven't been contacted in 30 days" into the correct SQL and run it. You do not need to know SQL yourself.

**Edge functions** are small pieces of serverless code that run on Supabase's infrastructure. They let you automate tasks that happen outside of Claude — scheduled data pulls, webhook receivers, automated reports. Think of them as the automation layer between your AI conversations and your data.

**Authentication** means Supabase can handle user logins for any application you build. If you ever create a web tool, a client portal, or an internal dashboard, Supabase Auth handles the sign-in flow securely — including Google, GitHub, and email/password options — without you writing authentication code from scratch.

:::{figure} ../images/ch03-supabase-free-tier.png
:label: fig-ch03-supabase-free
:alt: Supabase free tier limits — storage, API calls, edge functions, auth users
:width: 80%
:align: center

*The Free Tier* — Generous enough for real workflows. You will not hit these limits on a personal or small-team project.
:::

**Setting up Supabase:**

Go to supabase.com and create a free account. Create a new project — give it a name and a database password. Once provisioned (takes about two minutes), go to Project Settings → API and copy your Project URL and `anon` public key.

Add the Supabase MCP server to your Claude Desktop config:

```json
"supabase": {
  "command": "npx",
  "args": ["-y", "@supabase/mcp-server-supabase@latest",
           "--supabase-url", "your-project-url",
           "--supabase-key", "your-anon-key"]
}
```

Restart Claude Desktop. Ask Claude to list the tables in your Supabase database. If it responds with the schema, the connection is live.

From this point on, Claude can read and write to your Supabase database in any conversation. You can ask it to create a table for tracking leads, insert a row, query for records matching certain criteria, or update existing entries — all in plain English, no SQL required on your part.

## The Rest of the Landscape

The three tools above are the high-priority installs. But MCP is an ecosystem, not a closed list. Hundreds of servers exist and more are published every week. Here is a brief map of what else is available so you know where to look when you need something specific.

:::{figure} ../images/ch03-mcp-landscape.png
:label: fig-ch03-landscape
:alt: MCP tool landscape showing categories — code, web, data, productivity, infrastructure
:width: 80%
:align: center

*The MCP Landscape* — Categories of tools available. When you need a capability not covered in this chapter, this is how you find it.
:::

**Code and repositories** — GitHub MCP lets Claude read, write, and manage code repositories. If you work with developers or manage technical projects, this connection lets Claude participate in actual codebases rather than just talking about them abstractly.

**Web automation** — Chrome DevTools MCP gives Claude the ability to interact with web pages in a browser — filling forms, clicking buttons, extracting data from sites that Firecrawl cannot scrape because they require login sessions.

**Workflow automation** — Pipedream connects thousands of apps without code. Once integrated with Claude via MCP, it becomes a trigger-and-action engine: when Claude identifies something that needs to happen in another tool, Pipedream can make it happen.

**Infrastructure** — Netlify lets Claude deploy websites and web applications directly from a conversation. GoDaddy MCP covers domain management. These are niche tools for specific use cases but genuinely powerful when you need them.

**Finding new servers:** The canonical registry is at mcp.run and the Anthropic MCP GitHub repository. When you need a capability not covered here, search those first. The ecosystem is growing fast — if a major tool does not have an MCP server today, it likely will within months.

:::{figure} ../images/ch03-mcp-universal-pattern.png
:label: fig-ch03-universal
:alt: Four-step universal pattern for connecting any MCP server to Claude Desktop
:width: 80%
:align: center

*The Universal Pattern* — Find it, install it, configure it, verify it. Every MCP server follows this same four steps.

The universal pattern for any MCP server is the same four steps: find the server on GitHub or mcp.run, install it via npm or download the binary, add its entry to your `claude_desktop_config.json`, and restart Claude to verify the connection. Once you have done it three times, it becomes mechanical.

## Applied Exercise: Connect Google to Claude Desktop

By the end of this exercise you will have Gmail, Google Drive, and Google Calendar connected to Claude Desktop. You will prompt against your actual data and see what it returns. This is the moment the workshop becomes real.

**What you need before starting:**
- Claude Desktop installed (Chapter 2)
- A Google account (create one free at gmail.com if you do not have one)
- Node.js installed (nodejs.org — download LTS, install, verify with `node --version` in terminal)
- 30 minutes

**Part 1: Create Google API Credentials (15 minutes)**

1. Go to console.cloud.google.com and sign in with your Google account
2. Click **New Project** — name it "Claude MCP" — click Create
3. In the left sidebar, go to **APIs & Services → Library**
4. Search for and enable: **Gmail API**, **Google Drive API**, **Google Calendar API** — enable each one
5. Go to **APIs & Services → Credentials**
6. Click **Create Credentials → OAuth 2.0 Client ID**
7. Set the application type to **Desktop App** — name it anything — click Create
8. Download the JSON file — save it somewhere permanent on your computer (e.g., `~/claude-google-credentials.json`)

**Part 2: Update Your Claude Desktop Config (10 minutes)**

Open your config file:
- Mac: `~/Library/Application Support/Claude/claude_desktop_config.json`
- Windows: `%APPDATA%\Claude\claude_desktop_config.json`

Add the three Google servers, replacing `/path/to/your/credentials.json` with the actual path where you saved the file in Part 1. If you already have other MCP servers in the file, add these entries inside the existing `mcpServers` object.

Save the file and restart Claude Desktop.

**Part 3: Authenticate (5 minutes)**

The first time Claude tries to use a Google tool, a browser window will open asking you to sign in and grant permissions. Grant them. The authentication token is saved locally — you will not be asked again.

**Part 4: Prompt Against Your Real Data**

With Claude Desktop open, try each of these prompts one at a time:

*Gmail:*
> "Search my Gmail for any emails I received this week from someone I haven't replied to. List the sender, subject, and a one-line summary of what they need from me."

*Google Drive:*
> "Search my Google Drive for the most recently modified documents. List the five most recent ones with their titles and the last time they were edited."

*Google Calendar:*
> "Look at my Google Calendar for the next seven days. What meetings do I have? Are there any days with no meetings at all? Where is my biggest open block of time?"

Read each response carefully. Notice what Claude is actually seeing versus what it is inferring. If a response is wrong or incomplete, ask it to try again with a more specific query.
