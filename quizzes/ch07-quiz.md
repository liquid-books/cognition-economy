**Instructions:** Select the best answer for each question.

&nbsp;&nbsp;&nbsp;&nbsp;C. Their subscription tier does not include memory features; upgrading will resolve the issue.  
&nbsp;&nbsp;&nbsp;&nbsp;D. They need to switch to a different AI platform that stores conversation history in its training data.

**4.** A consultant is building her first memory file. She has drafted the following content: (1) her industry and advisory focus, (2) her three current engagements and their status, (3) the five client contacts who appear regularly in her work, (4) her preferences for how she wants information delivered, and (5) a complete archive of every proposal she has written over three years. Which edit produces the most effective memory file?

&nbsp;&nbsp;&nbsp;&nbsp;A. Remove items (1) and (4) — background and preferences are implicit and do not need to be stated.  
&nbsp;&nbsp;&nbsp;&nbsp;B. Expand item (5) by adding financial details and pricing to each proposal for richer context.  
&nbsp;&nbsp;&nbsp;&nbsp;C. Remove item (5) — a complete proposal archive is not a standing brief; those documents belong as task-level context within specific sessions, not in a memory file meant to be concise and current.  
&nbsp;&nbsp;&nbsp;&nbsp;D. Merge items (2) and (3) into a single narrative paragraph for readability.

**5.** Two colleagues use the same AI tool. Colleague A pastes every relevant contract, strategy document, and research report into a single master document they call their "memory file." Colleague B maintains a concise two-page brief of their role, active priorities, key relationships, and working preferences, and attaches relevant documents separately within each session. Over six months, whose approach is likely to yield more useful AI outputs, and why?

&nbsp;&nbsp;&nbsp;&nbsp;A. Colleague A, because the AI has access to more raw information and can surface deeper insights.  
&nbsp;&nbsp;&nbsp;&nbsp;B. Colleague B, because memory is a concise standing foundation while context — task-specific documents — is provided per session; conflating the two degrades both.  
&nbsp;&nbsp;&nbsp;&nbsp;C. Both approaches are equivalent; AI tools process all input with equal effectiveness regardless of structure.  
&nbsp;&nbsp;&nbsp;&nbsp;D. Colleague A, because thorough documentation is the hallmark of professional AI use.

## Answer Key

| Q | Answer | Rationale |
|---|--------|-----------|
| 1 | B | AI's stateless design clears the context window at session end — this is intentional, not a malfunction. The professional solution is a maintained memory file that restores standing context at the start of each session, eliminating the re-briefing tax. |
| 2 | C | Tier One disappears with each session; Tier Two requires manual re-attachment and cannot write back autonomously. Only Tier Three — a connected persistent database via MCP — allows an AI agent to store and retrieve structured information reliably across independent sessions over time. |
| 3 | C | The memory file's job is to be a concise, current standing brief. Accumulated meeting notes, completed projects, and one-time situations are not operationally relevant to future tasks. They force the AI to parse irrelevant detail, increasing latency and diluting the signal from what actually matters. |
| 4 | C | Items (1)–(4) are exactly what a memory file should contain: role, active engagements, key relationships, and preferences. A multi-year proposal archive belongs as task-level context attached to specific sessions — not as a permanent component of a standing brief meant to be short and current. |
| 5 | B | Memory and context serve distinct functions. Memory is the concise foundation; context is the session-specific material. Colleague A conflates them, creating noise. Colleague B preserves the distinction, ensuring each session opens with clean standing context and receives targeted material only when it is relevant. |
| 6 | B | A memory file should always reflect current reality. Completed projects accumulate as irrelevant history and undermine the file's precision. Sound curation means removing what is finished, updating what has changed, and keeping the file as a live snapshot — not a growing archive. |
| 7 | B | The compounding value argument is that memory engineering is not a static tool — it is a living asset. Each session reveals new preferences, constraints, and priorities that get refined into the file. After months of iteration, the memory file reflects a depth of calibrated context that cannot be replicated by someone starting fresh. |
| 8 | C | A memory file is a document with real exposure risk. Professional role, communication preferences, and reporting relationships carry relatively low risk. A confidential board-level restructuring plan requires deliberate evaluation: Who can see this file? What are the platform's data policies? What happens if this document is accessed unintentionally? |
| 9 | B | The AI's model weights do not change based on individual usage — it does not fine-tune on her behavior. The perceived shift from generic to calibrated is entirely structural: the memory file loads her specific role, priorities, and context into every session, giving the AI an accurate working model of her situation instead of defaulting to generic assumptions. |
| 10 | C | Regulated industries require deliberate privacy management, not blanket avoidance of AI tools. The sound approach is to evaluate the tool's data handling policies, keep sensitive case details out of persistent documents that travel across sessions, and provide confidential client context only within specifically vetted, session-bounded interactions. |
